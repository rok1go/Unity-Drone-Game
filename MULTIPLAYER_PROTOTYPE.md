# Прототип сетевых пряток

## Запуск

Открой сцену `Assets/Scenes/Main/Main.unity` и нажми Play: появится главное меню.
Windows-сборка создаётся через **Drone Game → Build multiplayer prototype**.
Готовый исполняемый файл: `Builds/MultiplayerPrototype/DroneHideAndSeek.exe`.
Другому игроку нужна вся папка сборки, включая `DroneHideAndSeek_Data` и DLL.

1. Хост выбирает **Играть → Создать лобби**, вводит имя и настройки.
2. Код лобби копируется кнопкой **Скопировать**.
3. Другой игрок выбирает **Играть → Присоединиться**, вводит код.
4. Игроки выбирают команды и нажимают **Готов**.
5. Хост нажимает **Начать матч**. Нужны минимум два игрока и обе команды.

Для двух копий на одном компьютере можно использовать Editor и Windows-сборку.
Каждый процесс использует отдельный профиль анонимной авторизации.
Для игры по коду нужен интернет и доступность сетевых служб связанного Unity-проекта.
Ошибки соединения показываются в меню; фиктивных кодов и локальной подмены подключения нет.

## Матч

- По умолчанию: 30 секунд пряток, 4 минуты поиска, 3 дрона на команду.
- Дроны заблокированы до конца фазы пряток.
- Потерянный дрон возвращается через 3 секунды, если в командном запасе есть свободный корпус.
- Люди выигрывают по времени, при исчерпании дронов или выходе всех пилотов.
- Дроны выигрывают после выбывания всех людей.
- Выбывшие люди наблюдают только за оставшимися людьми. Свободная камера в сетевом матче отключена.
- **Esc** открывает меню. Матч при этом продолжается.
- Хост может вернуть всех в лобби или запустить новый раунд после результата.
- Выход хоста завершает подключение остальных игроков.
- Новый раунд перезагружает исходную карту, восстанавливая здания и здоровье.

## Тренировка

Кнопка **Тренировка** запускает прежний локальный режим с переключением человека и дрона.
В тренировке **Tab** меняет роль, **R** выдаёт новый потерянный дрон или начинает следующий раунд.

## Устройство прототипа

- Unity Multiplayer Services SDK 2.4.1: сессии по коду и соединение через Relay.
- Netcode for GameObjects 2.13.3: транспорт и именованные сообщения.
- Хост определяет лобби, фазы раунда, HP, подрывы, запас дронов и результат.
- Владелец симулирует движение своего персонажа. Хост ограничивает передаваемые перемещения и рассылает положения остальных участников.
- Хост передаёт стабильные ID разрушенных блоков. Клиенты убирают соответствующие стены из геометрии и столкновений.
- Динамические тела обломков пока симулируются только на хосте; на клиентах синхронизируются отверстия и эффекты взрывов, а не полная физика каждого обломка.
- Подключение в уже начавшийся матч закрыто. Миграции хоста нет.

Компиляция и Windows-сборка проверяются отдельно от игрового прогона.
Проверку подключения двух игроков и ощущений от игры выполняет пользователь.
